# Quality Management Plan

## Project Title

**Evaluating Collaboration Tools for Effective Virtual IT Project Management: A Comparative Study of Jira, Microsoft Teams and Slack**

## 1. Purpose

The purpose of this Quality Management Plan is to define the standards and procedures that will be used to ensure the project is completed to an appropriate academic, research and project-management standard.

Quality will be considered throughout the project rather than only during final report preparation.

---

## 2. Quality Objectives

The project will aim to:

1. Produce accurate and reliable project documentation.
2. Use appropriate and credible academic sources.
3. Apply a consistent methodology.
4. Collect research data using appropriate procedures.
5. Protect research participant information.
6. Apply consistent evaluation criteria to all selected collaboration tools.
7. Analyse collected data systematically.
8. Ensure conclusions are supported by evidence.
9. Maintain accurate project records.
10. Deliver the final project within the agreed requirements and timeframe.

---

## 3. Quality Standards

The project will follow the following principles:

### Academic Quality

* Use credible academic and professional sources.
* Reference sources consistently.
* Avoid plagiarism.
* Distinguish clearly between evidence and personal interpretation.
* Ensure conclusions are supported by research findings.

### Project Management Quality

Project documentation should demonstrate appropriate use of:

* Scope management
* Schedule management
* Risk management
* Stakeholder management
* Communication management
* Quality management
* Change management

### Research Quality

Research activities should be:

* Systematic
* Transparent
* Consistent
* Ethical
* Appropriate to the research questions

---

---

## 5. Quality Assurance

Quality assurance focuses on preventing errors before they occur.

The project will use:

* Supervisor feedback
* Document reviews
* Questionnaire pilot testing
* Consistent evaluation criteria
* Version control through GitHub
* Regular project reviews
* Research methodology checks
* Data-quality checks

---

## 6. Quality Control

Quality control will be performed by reviewing completed work.

Examples include:

### Document Review

Each major document will be checked for:

* Accuracy
* Completeness
* Consistency
* Grammar
* Formatting
* References

### Data Quality Review

Before analysis, research data will be checked for:

* Missing values
* Duplicate responses
* Invalid responses
* Inconsistent entries
* Unnecessary personal information

### Analysis Review

Analysis will be checked to ensure:

* Calculations are correct.
* The appropriate data is being analysed.
* Charts represent the data accurately.
* Conclusions are supported by results.

---

## 7. Research Instrument Quality

The questionnaire will be reviewed before distribution.

The review will assess:

* Clarity of questions
* Relevance to research objectives
* Appropriate question wording
* Avoidance of leading questions
* Appropriate response scales
* Expected completion time

Where practical, the questionnaire will be piloted with a small number of people before wider distribution.

---

## 8. Collaboration Tool Evaluation Quality

Jira, Microsoft Teams and Slack will be evaluated using consistent criteria.

Potential criteria include:

1. Communication
2. Task management
3. Collaboration
4. Information sharing
5. Usability
6. Integration
7. Project visibility
8. Perceived productivity

The same evaluation framework will be applied to each selected tool to improve comparability.

---

## 9. Data Analysis Quality

Quantitative analysis will be conducted using appropriate statistical techniques.

Where Python is used, analysis scripts will be stored in the GitHub repository to improve reproducibility.

The analysis process will include:

1. Import data.
2. Inspect data.
3. Clean data.
4. Validate variables.
5. Calculate descriptive statistics.
6. Generate visualisations.
7. Interpret results.
8. Document findings.

Qualitative responses will be reviewed systematically and relevant themes will be identified.

---

## 10. Version Control

Git and GitHub will be used to maintain project version history.

The project will use meaningful commit messages such as:

```text
Add project charter
Add business case
Add stakeholder register
Add project schedule
Add risk register
Add questionnaire
Add data analysis
```

Major project changes should be committed separately where practical.

---

## 12. Quality Issues

Quality issues will be recorded when they could affect:

* Accuracy
* Research validity
* Project scope
* Schedule
* Data quality
* Academic standards
* Participant confidentiality
* Final project outcomes

Each significant issue will be assessed and an appropriate corrective action will be identified.

---

## 13. Quality Acceptance Criteria

The final project should:

* Address the stated research questions.
* Meet the project objectives.
* Contain appropriate research evidence.
* Use a consistent evaluation framework.
* Include analysed research data.
* Provide evidence-based findings.
* Provide practical recommendations.
* Include appropriate project-management documentation.
* Meet university academic requirements.
* Maintain appropriate data-protection standards.

---

## 14. Continuous Improvement

Lessons learned will be collected throughout the project rather than only at project closure.

Where an issue or improvement opportunity is identified, the Project Manager will consider whether the project process should be changed.

Examples include:

* Improving the questionnaire
* Changing the data-collection approach
* Adjusting the project schedule
* Improving documentation
* Changing communication frequency
* Improving data-analysis procedures
